## 有限前瞻做什么

`lookahead.py::LookaheadPolicy` 继承父任务的环形覆盖和阴性几何策略，只改变下一次测点。它把当前候选多边形分成 3 片，以各片面积和内部重心作为积分节点；对 18 个候选测点预测下一次读数，误差取 −1°、0°、+1°，再按 ±1.005° 构造预测后验。评分包括移动、读数、后续靠近、清除及补测代价。

对每个假想源，历史阳性和阴性给出未知 R 的允许区间；评分显式考虑收不到信的结果。这里的 R 分布只是选点模型，不用于删除真实候选。策略没有读取案例真值；真实更新和完整覆盖、光学兜底都保留。

384 例中，8 类场景的均值均有改善。CPU 时间约 40 秒，原基线约 8 秒；这是本机运行耗时，与平台虚拟时间分开。

横向扩充积分、再加光学尝试得到本组最低均值 230.21，但 CPU 约 70 秒，仍未到阈值。类位于 `screen_lookahead_transverse.py::TransverseOptical`，结果在 `p3_lookahead_transverse_v3_screen384.json`。若优先简洁，可保留 230.37 的三节点首版。

python -m unittest problem3.experiments_v3.test_journey_lookahead -v

## 没有采用的方向

- 将纵向积分加密到 7 点、显式展开第二次读数、与在途补测组合：前 96 例都没有超过首版前瞻。
- 每个扫描站都侧移 50–100 米补测，以及第二条正交共享基线：未超过原有首站共享基线。
- 从已成功清除点学习同心环的软先验：自然 96 例收益不稳定。在新增“前四点沿环，后续内散 / 第二环 / 偏心簇”的 96 个反例中，显式公共清除前缀下均值从 249.88 恶化为 253.65，因此否决。反例源参数只由外部案例生成器使用。
