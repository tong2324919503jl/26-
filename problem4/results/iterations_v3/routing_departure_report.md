# 第四问：21点覆盖后的调度尝试

这里均是自建 `development_v2`，不是平台成绩。算法只读取公开观测；事后下界审计单独使用真值，不进入算法。没有查看第三轮留出或压力集合，也没有改写生产算法。

共同基线是21个有证书的覆盖点，每站新发现频道先共享一次50米基线。384例全清，平均 **446.112秒/源**，400秒门槛通过125例。尚未达到400秒目标。

## 继续调度的结果

48例基线为438.448秒/源。下表分支均全清；有明显退化的方案没有继续扩大样本。

| 方法 | 48例平均秒/源 | 判断 |

| 用假想角度读数预测候选收缩，再选横移 | 439.273 | 没有改善 |

| 固定巡检路线加沿线共享测向 | 471.851 | 不能弥补延后服务的损失 |

另试“在可保证清除的位置集合内，选择离当前最近的点”：96例443.687秒/源，下降0.672秒，均全清。它用候选多边形各顶点的20米圆盘交集，选择最近可行点，不依赖方向先验。几何验证包含单点、线段、空交集和64组随机边界。第三问已有相近实现，若最终组合应统一共用代码，当前无需增加生产复杂度。

这些改动没有实质突破，因此没有将微小开发收益包装成最终方案，也没有继续盲目微调。

## 瓶颈与下界

21点共同基线的96例，移动按动作阶段划分：巡检腿14727.7米，定位腿5137.3米。每次定位从当时起点直接进入真实源20米邻域的事后几何下界，与实际定位腿只相差626.1米/例。局部定位的可省空间约10秒/源，主要空间在全局发现和覆盖顺序。

固定21点全频道巡检架构的96例下界：

- 少于16源的85例：平均至少392.907秒/源；全96例使用允许16源提前终止的放松后，平均至少363.491秒/源。
- 40例的下界已超过400秒。10、11、12源组的下界均值分别为501.742、452.783、407.161秒/源。
- 85例移动下界均18105米，明确构造的可行几何路线均18587米。后者是上界，不能写成最优值或下界。

该结论只适用于必须走完这21个固定巡检点的架构，不是不可能存在更快算法的证明，也不否定全样本平均400秒的可能。下界包含未知源首次发现的频道检测延迟，使用开放路径Held–Karp松弛与观测站接收集合的动态规划；24组小例与精确路径动态规划对照均通过。
