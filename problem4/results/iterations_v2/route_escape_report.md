# 第四问开放路线优化：Or-opt 与多起点

最终实现为 `problem4/routing.py` 的 `RoutingMixin`，仅依赖标准库与共用几何函数。2026-09-11 冻结，默认采用本文件下述方案。实际性能仍须由官方平台演练确认。

## 有效方案

把尚未扫描的位置、已发现源的候选区域中心视作待访问点，每次执行一个动作后重新规划开放路线：

1. 构造四条起始路线：最近邻、最便宜插入、顺时针角度顺序、逆时针角度顺序。
2. 额外保留上一轮的路线：删除已经完成的目标，把新增源插入代价最低的位置，减少滚动规划来回改变方向。
3. 每条路线先用 2-opt 反转子段；选出最短者后，用 Or-opt 搬移连续的 1、2、3 个访问点，最多16次搬移，每次后再做有界2-opt。单纯增加2-opt次数无法跨过的局部最优可因此被打破。
4. 末尾把未来扫频时间纳入小规模路线调整。离散的位置、距离、发射方向先验只估计未来需要扫多少未知频道，不用它删除候选区域或宣布覆盖完成。
5. 一旦已经发现16个不同频道，停止安排新的发现扫描；必须实际清除16个源才凭数量上限完成。剩余扫描列表不会被清空，故覆盖标记仍正确。

覆盖位置、定位区域、阴性剪枝及完成条件由独立组件负责。路由优化不改变它们。

## 同口径结果

开发集合 `development_v2`；全部使用 `coverage.static_coverage_points()` 的六位小数舍入坐标和生产版 `LocalizationMixin`。三组都384例全清且完成确认，未查看第二轮留出或压力集。

| 路线分支 | 平均秒/源 | 500秒/源阈值通过率 | 平均移动米 | 平均动作数 | 程序平均/最慢秒 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 信息成本 + 原2-opt | 495.783 | 51.823% | 22504.199 | 296.060 | 0.136 / 0.250 |
| 保留前轮路线 + Or-opt | 489.038 | 54.688% | 21942.437 | 301.784 | 0.074 / 0.193 |
| **四起点 + 保留前轮路线 + Or-opt + 信息成本** | **483.724** | **55.469%** | **21806.944** | **293.833** | **0.147 / 0.265** |

在这三组中，按“全部清除、阈值通过率、平均耗时”的顺序选择最后一组。与原2-opt信息路线相比，移动减少约697米/例，阈值通过率提高3.646个百分点。这里的程序耗时不含HTTP延迟，是本机本地计算时间。

同舍入坐标前96例筛查中，纯Or-opt阈值52.08%、保留前轮路线+Or-opt53.125%、后者加信息成本51.04%、完整组合54.17%；没有因某一小样本的均值更低就直接选型。未舍入坐标的早期试验单独保存，不能与这张表混用，因为地点固定的误差场可能因坐标舍入而改变。
